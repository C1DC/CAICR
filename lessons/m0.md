## 4. The command line, and why it is non-negotiable

A graphical interface shows you what someone decided to show you. The command
line shows you *everything*, exactly, and lets you combine small tools into
powerful investigations. Security work is about precision and evidence: the
terminal gives you both, and it scripts and repeats. Every serious tool in this
field is driven from it.

The shell prompt tells you who and where you are:

```
┌──(kali㉿kali)-[~]
└─$
```

`kali@kali` is *user@host*; `~` is your current directory (your home folder);
`$` means a normal user (a `#` would mean root). Read the prompt before you type.

## 5. The Linux command line — the commands that matter

Work through these at the terminal. Each block is real; type them, don't just
read them. Everything here you will use again in the labs.

### 5.1 Who and where am I?

```
whoami              # your username
id                  # your user id, groups (shows if you have sudo/root power)
hostname            # the machine's name
pwd                 # "print working directory" — where you are right now
uname -a            # kernel and architecture — know the system you're on
date                # current date/time (matters for evidence timestamps)
```

A security professional *always* knows which account they are using and on which
host. Acting as the wrong user, on the wrong box, is how mistakes and incidents
happen.

### 5.2 Getting help — the habit that makes you self-sufficient

```
man nmap            # the full manual for a command (press q to quit, / to search)
nmap --help         # quick option summary
whatis grep         # one-line description
apropos password    # find commands related to a keyword
```

Nobody memorises every flag. Professionals read the manual fast. `man` is your
first move with any unfamiliar tool.

### 5.3 Moving around the filesystem

Linux is a single tree starting at `/` (root). Everything hangs off it.

```
ls                  # list files here
ls -la              # long listing, including hidden files (names starting with .)
ls -lh              # human-readable sizes (K, M, G)
cd /etc             # change to an absolute path
cd ..               # up one level
cd ~                # home;  cd -  returns to the previous directory
tree -L 2           # a visual tree, two levels deep
```

Paths are **absolute** (start with `/`, e.g. `/etc/passwd`) or **relative** (from
where you are, e.g. `../logs`). `.` is here, `..` is the parent, `~` is home.

### 5.4 Reading files

```
cat notes.txt               # dump a whole file
less /var/log/syslog        # page through a big file (q to quit, / to search)
head -n 20 file             # first 20 lines
tail -n 20 file             # last 20 lines
tail -f /var/log/auth.log   # follow a log live as it grows — vital in IR
file evidence.img           # what KIND of file is this, really?
strings binary.bin          # pull readable text out of a binary (find URLs, keys)
xxd capture.bin | head      # raw hex view — forensics bread and butter
```

`file`, `strings` and `xxd` are the ones beginners skip and professionals live
on — they tell you what something actually is when the extension lies.

### 5.5 Creating, copying, moving, deleting

```
mkdir -p cases/2026/incident-07   # make nested directories in one go
touch report.md                   # create an empty file / update its timestamp
cp -r evidence/ evidence-copy/     # copy (work on COPIES, never originals)
mv draft.md final.md               # move or rename
rm file.txt                        # delete a file
rm -rf folder/                     # delete a folder and everything in it
```

> `rm -rf` is irreversible and asks no questions. There is no recycle bin. Read
> the path twice before you press Enter — especially as root.

### 5.6 Finding things

```
find /home -name "*.pcap"             # by name, anywhere under /home
find . -type f -mtime -1              # files modified in the last day (IR triage)
find / -perm -4000 -type f 2>/dev/null  # setuid binaries — classic priv-esc hunt
which nmap                            # where a command lives on disk
grep -r "password" /etc/ 2>/dev/null  # search file CONTENTS recursively
```

`find` and `grep -r` are how you locate a needle — a leaked credential, a
recently changed file, a dangerous permission — in a haystack of thousands of
files.

### 5.7 Pipes and redirection — the real power

This is the idea that makes the command line powerful: small tools, chained.
`|` sends one command's output into the next; `>` writes to a file; `>>`
appends; `2>` redirects errors.

```
cat auth.log | grep "Failed password" | wc -l     # count failed SSH logins
nmap -sV 10.13.3.0/24 > scan.txt                   # save output to a file
command 2>/dev/null                                # throw errors away
command > out.txt 2>&1                             # capture output AND errors
dig TXT example.com | tee dns.txt                  # show on screen AND save
```

"Count the failed logins, by source IP, sorted by most frequent" becomes one
line — you'll build exactly that in Module 4.

### 5.8 Text processing — turning data into answers

```
grep -i "error" log        # -i ignore case
grep -E "T10[0-9]{2}" f    # -E extended regex (match ATT&CK IDs like T1046)
grep -v "healthcheck" log  # -v invert: everything EXCEPT matches
grep -c "fail" log         # -c count matching lines
cut -d',' -f1,3 data.csv   # pull columns 1 and 3 from a CSV
sort file | uniq -c | sort -rn   # count duplicates, most-frequent first
awk '{print $1}' access.log | sort | uniq -c   # top source IPs from a log
sed 's/old/new/g' file     # stream-edit: replace text
wc -l file                 # count lines
```

The pattern `sort | uniq -c | sort -rn` — "what are the most common values?" — is
one of the most useful lines in all of security analysis. Memorise it.

### 5.9 Permissions and ownership

Every file has an owner, a group, and three permission sets — for the **owner**,
the **group**, and **everyone else** — each granting read (`r`), write (`w`) and
execute (`x`).

```
ls -l script.sh
# -rwxr-xr--  1  kali  kali  ...  script.sh
#  │└┬┘└┬┘└┬┘
#  │ │  │  └ others: read only
#  │ │  └─── group: read + execute
#  │ └────── owner: read + write + execute
#  └──────── type: - file, d directory, l link
```

```
chmod +x labctl        # make a file executable
chmod 640 secret.txt   # owner rw, group r, others none  (4=r 2=w 1=x)
chmod 600 id_rsa       # private keys MUST be owner-only, or SSH refuses them
chown kali:kali file   # change owner and group (usually needs sudo)
umask                  # the default permissions mask for new files
```

Permissions are a security control in their own right. A world-readable
`config.php` with a database password in it — which you'll find in Module 4 — is
a permissions failure.

### 5.10 Users, privilege and sudo

```
sudo <command>     # run one command as root (you'll be asked for your password)
sudo -l            # what am I allowed to run as root? (attackers check this)
su - username      # switch to another user
cat /etc/passwd    # the list of accounts on the system
who ; last         # who is logged in now; login history
```

Root (uid 0) can do anything. Use `sudo` deliberately, never habitually.
Over-use of root is how a small mistake becomes a catastrophe.

### 5.11 Processes and services

```
ps aux                 # every running process (a = all, u = detailed, x = incl. daemons)
ps aux | grep ssh      # is sshd running?
top        (or htop)   # live process/resource monitor (q to quit)
kill 1234              # stop process id 1234 politely
kill -9 1234           # force-kill (last resort)
jobs ; fg ; bg         # manage jobs you backgrounded with &
nohup long-task &      # keep a task running after you log out
systemctl status docker # the state of a system service
sudo systemctl start docker
```

In incident response, `ps aux` is often your first look at *what is actually
running* on a suspect machine — including the thing that should not be.

### 5.12 Networking from the terminal

```
ip a                  # your network interfaces and IP addresses (modern)
ip r                  # the routing table
ping -c 4 10.13.3.10  # is a host reachable? (4 packets)
ss -tulpn             # listening TCP/UDP ports and the processes behind them
dig example.com MX    # query DNS (Modules 1 & 5)
host example.com      # quick DNS lookup
whois example.com     # domain registration details
curl -I https://site  # fetch just the HTTP response headers
curl -s https://site/api | less   # fetch a page/API quietly
wget https://site/file           # download a file
nc -lvnp 4444         # netcat: listen on a port (the Swiss-army knife of networking)
```

`ss -tulpn` answers "what is this machine exposing to the network?" — the single
most important question when you harden a server. You'll use `dig`, `whois` and
`curl` directly in the labs.

### 5.13 Packages — installing tools

```
sudo apt update                 # refresh the package list
sudo apt install -y wireshark   # install a tool
apt search forensic             # find packages
dpkg -l | grep nmap             # is it already installed?
```

### 5.14 Archives, transfer and integrity

```
tar -czf case.tar.gz case/      # create a compressed archive
tar -xzf case.tar.gz            # extract one
zip -r out.zip folder/ ; unzip out.zip
base64 -d artifact.b64          # decode Base64 (Module 6)
sha256sum evidence.img          # fingerprint a file — proof of integrity
sha256sum -c evidence.sha256    # verify it hasn't changed
```

`sha256sum` is the backbone of chain of custody in Module 6. A hash proves, with
mathematics, that evidence was not altered.

### 5.15 System and disk

```
df -h          # disk space per filesystem, human-readable
du -sh *       # size of each item in the current directory
free -h        # memory usage
uptime         # how long the system's been up, and load
lsblk          # block devices / disks (useful before imaging in forensics)
```

### 5.16 History, shortcuts and speed

```
history          # your command history
!!               # repeat the last command (e.g. sudo !!)
!$               # the last argument of the previous command
```

Learn these keystrokes — they pay off every single day:

- **Tab** — auto-complete commands and paths (use it constantly).
- **Ctrl‑R** — reverse-search your history (type a few letters of an old command).
- **Ctrl‑C** — cancel the running command.
- **Ctrl‑L** — clear the screen (same as `clear`).
- **Ctrl‑A / Ctrl‑E** — jump to the start / end of the line.
- **Ctrl‑D** — end of input / log out.
- **↑ / ↓** — previous / next command.

Environment and the `$PATH` (where the shell looks for commands):

```
echo $PATH                 # the directories searched for commands
export TARGET=10.13.3.10    # set a variable for this session
echo $TARGET
```

## Key takeaways

- The terminal is where security work actually happens — fluency is the
  foundation everything else is built on.
- **Pipes** (`|`) chain small tools into powerful one-liners;
  `sort | uniq -c | sort -rn` answers "what's most common?".
- Know your identity and host at all times (`whoami`, `id`, `hostname`).
- `find`, `grep -r`, `file`, `strings`, `ss -tulpn`, `ps aux` and `sha256sum`
  are the workhorses you'll reach for again and again.

## Check yourself

1. **You need the five most frequent source IPs in a web log's first column.
   Write the one-liner.**
   → `awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5`.

2. **`ls -l` shows `-rw-------` on `id_rsa`. Good or bad, and why?**
   → Good — a private key must be readable only by its owner (`600`). SSH will
   refuse a key that others can read.

3. **What does `ss -tulpn` tell you, and when is it your first command?**
   → The listening TCP/UDP ports and the processes behind them — your first
   command when assessing what a machine exposes to the network.

4. **Why do forensic examiners run `sha256sum` before and after handling
   evidence?**
   → To prove mathematically that the evidence was not altered — the foundation
   of chain of custody.

5. **A colleague asks you to "just quickly scan" a partner company's website to
   check it's secure. Your response?**
   → No — not without that company's written authorisation. Scanning a third
   party is an offence under Act 1038, regardless of good intentions.

## Glossary

- **Shell** — the program that interprets your commands (Bash/Zsh).
- **Path (absolute/relative)** — a file's location from `/` or from where you are.
- **Pipe `|`** — send one command's output as the next command's input.
- **Redirection `>` `>>` `2>`** — send output/errors to a file.
- **Permissions (rwx)** — read/write/execute for owner, group, others.
- **sudo / root** — run as the all-powerful administrator (uid 0).
- **PATH** — the directories the shell searches for commands.
- **Hash (sha256)** — a file's unique fingerprint, used to prove integrity.
