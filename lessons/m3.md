# Module 3 — Network, Endpoint & Identity Security

**Day 2 · Morning · Hands-on lab: `labctl start m3`**

In one sentence: you learn to see a network the way both an attacker and a
defender do — what's exposed, what's talking to what, and which conversation is
the compromise hiding in plain sight.

By the end you will be able to:
- map a network with Nmap: live hosts, open ports, running services;
- read captured traffic in Wireshark and spot command-and-control beaconing;
- explain why segmentation, DNS monitoring and MFA are the controls that matter;
- map what you find to MITRE ATT&CK.

## The big picture

A network is just computers having conversations. Every conversation uses
**ports** (numbered doors) and **protocols** (languages). Web traffic uses port
80/443 (HTTP/HTTPS), remote login uses 22 (SSH) or 3389 (RDP), mail uses 25, DNS
uses 53. An attacker's first question on your network is simple: *which doors are
open, and what's standing behind them?*

**Active scanning** answers that. Unlike the passive recon of Module 1, here you
send packets to the targets and watch what comes back. That's why it is done
**only** on networks you own or are authorised to test — in this course, only the
isolated `10.13.3.0/24` range.

Two instruments do most of the work:

- **Nmap** — the scanner. It finds live hosts, open ports, the software and
  version behind each port, and can even guess the operating system.
- **Wireshark** (and its command-line cousin **tcpdump**) — the microscope. It
  shows you the actual packets so you can read a conversation and judge whether
  it's normal or malicious.

The **identity layer** sits on top: it's not enough to know *what* connects —
you must know *who*. That's authentication (proving identity) and authorisation
(what you're allowed to do). Weak identity is how most breaches escalate.

## An analogy

Nmap is walking the corridors of a building at night, trying every door handle
and noting which rooms are unlocked and what's inside ("this one's a server
room, this one's an old photocopier running Windows XP"). Wireshark is then
putting a wiretap on the phone line and *listening to the calls* — most are
routine, but one extension dials the same foreign number every 30 seconds, at
exactly the same interval, all night. No human works like that. That regular
"heartbeat" is malware checking in with its controller.

## How it actually works

A typical Nmap workflow, from quiet to loud:

- `nmap -sn 10.13.3.0/24` — *host discovery*: who's alive? (No port scan.)
- `nmap -sV -p 21,22,80,443,3389 10.13.3.0/24` — *service/version detection*:
  what's running, and is it old?
- `nmap --script=http-title ...` — run a script to grab extra detail (here, web
  page titles — handy for spotting an unauthenticated admin panel).

What you're hunting for: things that **shouldn't be exposed** — RDP (3389) open
to everyone, unencrypted FTP (21), an admin console with no login. Each is a door
left wide open.

Then the traffic. In Wireshark you apply a **display filter** (e.g. `dns`) to cut
the noise. **Command-and-control (C2) beaconing** is the classic giveaway: a
compromised host repeatedly contacting the same external domain at a **fixed
interval**. The regularity is the tell — legitimate traffic is bursty and
irregular; malware is a metronome. Roughly **90% of malware uses DNS** to find
its controller, which is why DNS monitoring is such a powerful early warning.

Map the findings to **MITRE ATT&CK**: network scanning is **T1046** (Network
Service Discovery); the beaconing is **T1071** (Application Layer Protocol),
sub-technique **T1071.004** for DNS.

The four controls that answer all of this:

- **Network segmentation** — a flat network lets an attacker roam; segments
  contain them.
- **DNS monitoring** — catches the beacon.
- **MFA on remote access** — stops a stolen RDP/SSH password being enough.
- **A firewall rule** — close 3389 to the internet; put it behind a VPN.

## Ghana in focus

Many West African breaches begin with an exposed remote-access service — an RDP
port left open "temporarily" for a vendor, then forgotten. Automated attackers
scan the entire internet continuously; an exposed 3389 in Accra is found within
hours, not weeks. The lesson every Ghanaian IT team should internalise: *scan
your own network monthly* with the very same Nmap, before someone else does.
Finding your own open RDP is free; having it found for you costs a ransom.

## Why it matters

- You cannot protect what you cannot see — scanning gives you the real inventory,
  which is almost always different from the one on paper.
- Reading traffic turns "the antivirus is quiet" into actual evidence of what a
  host is doing.
- Catching a beacon early is the difference between an incident and a breach.

## Common mistakes

- **Scanning outside your authorisation.** Nmap against a network you don't own
  is an offence under Act 1038. In the lab: only `10.13.3.x`.
- **Confusing capture and display filters** in Wireshark — a capture filter
  decides what's recorded; a display filter decides what's shown.
- **Dismissing "small" open ports.** An unauthenticated admin panel on an obscure
  port is a full compromise waiting to happen.
- **Treating encrypted = safe.** TLS hides content, not the *pattern*; beaconing
  is visible even when the payload isn't.

## Do it yourself

`labctl start m3` brings up a four-host enterprise subnet (web admin, FTP, SSH,
legacy RDP) plus a packet capture. Discover the hosts, find the exposed services,
then open the capture in Wireshark, filter to `dns`, and identify the C2 domain
and its beacon interval. `labctl verify m3` grades each finding.

## Key takeaways

- **Ports are doors, protocols are languages**; Nmap finds the open doors.
- Active scanning is **authorised-targets-only**.
- **C2 beaconing = same destination, fixed interval** — regularity is the tell.
- Most malware phones home over **DNS** — monitor it.
- Controls: **segmentation, DNS monitoring, MFA on remote access, firewall
  rules.** ATT&CK: **T1046**, **T1071**.

## Check yourself

1. **`nmap -sn` versus `nmap -sV` — what's the difference?**
   → `-sn` only discovers which hosts are alive (no port scan); `-sV` scans ports
   and identifies the service and version behind each open one.

2. **In a capture you see one host query `cdn-update.ddns.net` every 60 seconds,
   all night. Benign or suspicious, and why?**
   → Suspicious: the fixed, regular interval is classic C2 beaconing. Real user
   traffic is irregular.

3. **RDP (3389) is open to the internet. Name two controls.**
   → Put it behind a VPN / close the port at the firewall, and require MFA on the
   account. (Network segmentation also helps.)

4. **Which ATT&CK technique covers an internal host scanning the network?**
   → T1046, Network Service Discovery.

## Glossary

- **Port** — a numbered endpoint for a network service (e.g. 22 = SSH).
- **Nmap** — network scanner for host/port/service discovery.
- **Wireshark / tcpdump** — packet analysers (GUI / CLI).
- **C2 (command and control)** — the channel malware uses to reach its operator.
- **Beaconing** — regular, interval-based check-ins from malware to C2.
- **Segmentation** — dividing a network so a breach in one part can't reach all.
