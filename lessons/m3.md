# Module 3 — Network, Endpoint & Identity Security

**Day 2 · Morning · Hands-on lab: `labctl start m3`**

You learn to see a network the way both an attacker and a defender see it — what
is exposed, what is talking to what, and which conversation is the compromise
hiding in plain sight — then you prove it with the two instruments every network
investigator lives on: Nmap and Wireshark.

By the end you will be able to:
- map a network with Nmap (hosts, ports, services, versions) and read the output;
- analyse captured traffic in Wireshark and identify command-and-control
  beaconing;
- explain segmentation, defence-in-depth, Zero Trust and the identity layer;
- map findings to MITRE ATT&CK and prescribe the controls that close the gaps.

---

## 1. The big picture: a network is conversations

Every network is computers having conversations, each using a **port** (a
numbered door) and a **protocol** (a language). The models that organise this —
the **OSI** seven layers and the practical **TCP/IP** stack — matter because
attacks and defences live at specific layers: a port scan at layer 4, a C2
domain lookup at layer 7, ARP spoofing at layer 2. Know the layer and you know
the control.

An attacker's first question on any network is blunt: **which doors are open, and
what is standing behind them?** Your job is to answer it about your own estate
before they answer it about you.

Two defensive ideas frame everything:

- **Defence in depth** — no single control is trusted; you layer them, so one
  failure is not fatal.
- **Zero Trust** — "never trust, always verify". The old model trusted anything
  *inside* the perimeter; Zero Trust assumes the attacker is already inside and
  authenticates every request. A **flat network** (everything can reach
  everything) is the opposite — and a catastrophe waiting to happen.

## 2. The identity layer — who, not just what

Knowing *what* connects is not enough; you must know *who*. **Authentication**
proves identity; **authorisation** decides what that identity may do. Weak
identity is how most breaches *escalate* from a toehold to a disaster:

- **MFA** matters more than almost any other control. But not all MFA is equal:
  SMS one-time codes are phishable and defeated by SIM-swap (Module 5); TOTP
  authenticator apps are better; **phishing-resistant FIDO2/passkeys** are best.
- **Privileged Access Management (PAM)** — just-in-time admin access, vaulted
  credentials, session recording — contains the damage when an account is taken.
- **Anomalous-login signals** — impossible travel, new device + new location,
  off-hours privileged access — are among your most reliable detections.

## 3. How the tools actually work

**Nmap** — the scanner. A workflow from quiet to loud:

```
nmap -sn 10.13.3.0/24                      # host discovery: who is alive?
nmap -sV -p 21,22,80,443,3389 10.13.3.0/24 # service + version detection
nmap -A 10.13.3.5                          # aggressive: OS guess, scripts, traceroute
nmap --script=http-title -p80 10.13.3.0/24 # run an NSE script
nmap -oN scan.txt 10.13.3.0/24             # save evidence
```

You are hunting for what **should not be exposed**: RDP (3389) reachable by
anyone, unencrypted FTP (21), an admin console with no authentication. Each is a
door left open. The **Nmap Scripting Engine (NSE)** adds hundreds of checks for
specific weaknesses.

**Wireshark / tcpdump** — the microscope. Apply a **display filter** (e.g. `dns`)
to cut noise. The classic finding is **command-and-control (C2) beaconing**: a
compromised host contacting the same external destination at a **fixed interval**.
Legitimate traffic is bursty and irregular; malware is a metronome, and that
regularity is the tell. Roughly **90% of malware uses DNS** to reach its
controller, which is why DNS monitoring is such a powerful early warning.

```
tcpdump -i eth0 -w capture.pcap            # capture to a file
tcpdump -r capture.pcap 'udp port 53'      # read back, DNS only
```

Map findings to **MITRE ATT&CK**: scanning is **T1046** (Network Service
Discovery); internal reconnaissance and spread is Lateral Movement (e.g.
**T1021** Remote Services); beaconing is **T1071** (Application Layer Protocol),
sub-technique **T1071.004** for DNS.

## 4. An analogy

Nmap is walking a building's corridors at night, trying every door handle and
noting which rooms are unlocked and what's inside ("server room… an old
photocopier still running Windows XP"). Wireshark is then tapping the phone line and
*listening*: most calls are routine, but one extension dials the same foreign
number every sixty seconds, all night. No employee behaves like that. That
heartbeat is malware checking in with its operator.

## 5. Scenarios — why flat networks and exposed services cost millions

### Local (Ghana / West Africa)

- Many West African breaches begin with an **exposed remote-access service** — an
  RDP port opened "temporarily" for a vendor and forgotten. Internet-wide
  scanners find it within hours. The discipline that prevents it is free: **scan
  your own network monthly** with the same Nmap, before someone else does.
- Cloud misconfiguration is the regional epidemic — public storage buckets, open
  databases, default admin credentials. Audit cloud permissions quarterly.

### International (well-documented)

- **Target, 2013 (~40M payment cards).** Attackers entered through an HVAC
  *vendor's* credentials, then moved freely because the network was **flat** —
  the vendor segment could reach the payment systems. Segmentation would have
  contained it. A textbook Lateral Movement case.
- **NotPetya, 2017.** Once inside, the worm spread uncontrolled across flat,
  trusted internal networks, reaching global scale in hours. Zero Trust and
  segmentation are the architectural answers to exactly this.

The through-line: the *initial* foothold is often small; the catastrophe comes
from a flat network and weak identity that let it spread.

## 6. Why it matters

- You cannot protect what you cannot see — scanning gives you the *real*
  inventory, which is almost always different from the one on paper.
- Reading traffic turns "the antivirus is quiet" into actual evidence of what a
  host is doing.
- Catching a beacon early is the difference between an *incident* and a *breach*.

## 7. Common mistakes

- **Scanning outside your authorisation** — Nmap against a network you don't own
  is an offence under Act 1038. In the lab: only `10.13.3.x`.
- **Confusing capture and display filters** — a capture filter decides what is
  recorded; a display filter decides what is shown.
- **Dismissing a "small" open port** — an unauthenticated admin panel is a full
  compromise waiting to happen.
- **Assuming encrypted = safe** — TLS hides content, not the *pattern*; beaconing
  is visible even when the payload is not.

## Do it yourself

`labctl start m3` brings up a four-host enterprise subnet (web admin, FTP, SSH,
legacy RDP) plus a packet capture. Discover the hosts, find the exposed services,
then open the capture in Wireshark, filter to `dns`, and identify the C2 domain
and its beacon interval. Recommend four controls and map to ATT&CK.
`labctl verify m3` grades your findings.

## Key takeaways

- **Ports are doors, protocols are languages;** Nmap finds the open doors, from
  quiet (`-sn`) to loud (`-A`).
- **Defence in depth** and **Zero Trust**; a **flat network** turns a toehold
  into a catastrophe.
- Identity is the escalation layer — **phishing-resistant MFA** and **PAM** matter
  most.
- **C2 beaconing = same destination, fixed interval**; most malware beacons over
  **DNS**. ATT&CK: **T1046, T1021, T1071**.

## Check yourself

1. **`nmap -sn` vs `nmap -sV` — what does each do?**
   → `-sn` only discovers which hosts are alive (no port scan); `-sV` scans ports
   and identifies the service and version behind each open one.

2. **In a capture one host queries `cdn-update.ddns.net` every 60 seconds all
   night. Benign or suspicious, and why?**
   → Suspicious — the fixed, regular interval is classic C2 beaconing; genuine
   user traffic is irregular.

3. **Target 2013: the entry was an HVAC vendor's account, but the catastrophe was
   architectural. What was the architectural failure?**
   → A flat network — the vendor segment could reach the payment systems.
   Segmentation (and Zero Trust) would have contained the intrusion.

4. **Why is SMS-based MFA weaker than a FIDO2 security key?**
   → SMS codes are phishable and defeated by SIM-swap; FIDO2/passkeys are
   phishing-resistant and bound to the legitimate site.

## Glossary

- **Port / protocol** — a numbered service endpoint / the language it speaks.
- **OSI & TCP/IP** — the layer models that locate attacks and controls.
- **Defence in depth** — layered controls so one failure isn't fatal.
- **Zero Trust** — never trust, always verify; assume breach.
- **Segmentation** — dividing a network so a breach in one part can't reach all.
- **C2 / beaconing** — malware's control channel / its regular check-ins.
- **PAM / MFA** — privileged access management / multi-factor authentication.
- **NSE** — the Nmap Scripting Engine.
