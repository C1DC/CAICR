## The big picture

**Vulnerability management** is a cycle, not a one-off scan: *find → prioritise →
fix → verify → repeat.* Scanning is the easy part; a scanner will hand you
hundreds of findings. The real work is **prioritisation**, because you can't fix
everything at once.

A good priority score combines four things:

- **CVSS** — a 0–10 severity score for the vulnerability itself.
- **Exploitation status** — is it being actively exploited *right now*? The free
  **CISA KEV** (Known Exploited Vulnerabilities) catalogue tells you.
- **Exposure** — is it internet-facing or buried internally?
- **Asset criticality** — is it your payroll database or a test box?

A medium-CVSS bug that is internet-facing, on a critical system, and listed in
KEV beats a "critical" CVSS bug that's internal and never exploited. Context
wins.

The **SOC (Security Operations Centre)** is the other half: the team (or person)
watching the alerts. Their core skill is **triage** — quickly deciding, for each
alert, true positive / false positive / needs investigation, and escalating the
ones that matter.

## An analogy

A vulnerability scan is a home inspector's report: it lists *every* defect, from
"roof could collapse" to "one loose cupboard hinge". If you treat them all as
equally urgent you'll fix hinges while the roof caves in. Prioritisation is
reading that report like an adult: roof first.

SOC triage is a hospital emergency room. Patients (alerts) arrive constantly.
You can't deep-treat everyone at once, so you *triage*: this one's critical (real
attack), this one's fine (false alarm), this one needs tests (investigate). Alert
fatigue is the tired nurse who starts waving everyone through — which is exactly
when the real emergency slips past.

## How it actually works

**Nikto** scans web servers specifically — it looks for dangerous files, leftover
backups, outdated software and missing security headers. Where Nmap tells you
*port 80 is open*, Nikto tells you *what's wrong with what's running on it*: an
exposed `/admin/` panel, a `config.php.bak` leaking database credentials, a
`phpinfo.php` spilling server internals.

**Password attacks** come in two flavours, and the lab shows both:

- **Hydra** — *online* guessing: it tries username/password pairs against a live
  service (e.g. SSH). Noisy, slow, but deadly against weak passwords. A
  "password-spray" tries one common password across many accounts to dodge
  lockouts.
- **John the Ripper** — *offline* cracking: given stolen password *hashes*, it
  computes guesses locally at huge speed. No network, no lockout, no limit.

The point of both is not "how to hack" — it's **why controls are mandatory**: a
password in a wordlist is already broken, which is why length, uniqueness and
especially **MFA** matter. MFA means a cracked password alone isn't enough.

**SIEM triage** ties it together. A SIEM (here, **Wazuh**) collects logs from
many systems and raises **alerts** with a severity *level* and often an ATT&CK
mapping. Triage workflow: sort by severity → add context → decide TP/FP/investigate
→ escalate or close. The master skill is **correlation**: ten alerts aren't ten
problems — they're often one attack seen from ten angles. Failed SSH logins
(brute force) + a port scan + a *successful* login, all from the *same source
IP*, is not three events. It's one intrusion, and the attacker is now inside.

Brute force maps to ATT&CK **T1110**.

## Ghana in focus

Picture a SOC analyst at a Ghanaian bank at 2 a.m. Wazuh shows dozens of
"failed SSH login" alerts — individually low severity, easy to ignore when
you're tired. But one source IP is behind all of them, and minutes later there's
an "authentication success" from that same IP, then a "sudo to root". Read
individually: noise. Correlated: a brute-force that *succeeded* and escalated to
admin. The institutions that get breached aren't the ones without alerts — they
had the alerts. They're the ones who didn't correlate them in time.

## Why it matters

- Prioritisation turns an unmanageable scan report into a short, fundable
  remediation list.
- Understanding password cracking is the argument that finally gets MFA approved.
- Correlation is what converts raw alerts into an actionable incident before the
  damage is done.

## Common mistakes

- **Chasing CVSS alone.** A 9.8 nobody can reach matters less than a 6.5 on your
  internet-facing payroll box that's in KEV.
- **Using Hydra/John outside the lab.** Only the authorised lab targets and the
  provided hash file — anywhere else is a crime.
- **Closing alerts to clear the queue.** "Mark as resolved" without investigating
  is how breaches hide.
- **Ignoring low-severity floods.** Volume *is* a signal; many low alerts from
  one source can be a single high-severity attack.

## Do it yourself

`labctl start m4` gives you a leaky web server (for Nikto), an SSH box with a weak
account (authorised Hydra target), a hash file (for John), and a realistic Wazuh

> On Wazuh in this course: you triage a realistic alert feed rather than run a
> full SIEM stack, because a complete Wazuh deployment needs far more RAM than a
> classroom laptop has. The skill — triage and correlation — is identical.

## Key takeaways

- Vulnerability management = **find → prioritise → fix → verify**, looping.
- Prioritise by **CVSS + KEV + exposure + asset criticality**, not CVSS alone.
- **Hydra** = online guessing; **John** = offline hash cracking; **MFA** defeats
  both.
- SIEM triage = **TP / FP / investigate**; the real skill is **correlation**.
- Brute force is ATT&CK **T1110**.

## Check yourself

1. **Two findings: CVSS 9.1 on an internal test server (not in KEV); CVSS 6.8 on
   your public payment portal, listed in CISA KEV. Which first?**
   → The 6.8 — it's internet-facing, on a critical asset, and *actively
   exploited*. Context beats raw score.

2. **Hydra vs John — what's the core difference?**
   → Hydra guesses against a live service (online); John cracks stolen hashes
   locally (offline). John has no lockout or rate limit.

3. **You see failed logins, a port scan and a successful login — all from
   10.0.0.9. How many incidents?**
   → One. Correlate by source IP: it's a single intrusion that succeeded, not
   three separate events.

4. **A cracked password is bad — what single control makes it insufficient on its
   own?**
   → MFA (multi-factor authentication).

## Glossary

- **CVSS** — 0–10 severity score for a vulnerability.
- **CISA KEV** — free catalogue of vulnerabilities known to be actively exploited.
- **Nikto** — web-server vulnerability scanner.
- **Hydra / John the Ripper** — online password guesser / offline hash cracker.
- **SIEM** — Security Information and Event Management; collects logs, raises
  alerts (e.g. Wazuh).
- **Triage** — rapidly classifying alerts as true/false positive or
  needs-investigation.
