# Module 4 — Vulnerability Management & SOC Operations

**Day 2 · Afternoon · Hands-on lab: `labctl start m4`**

Finding weaknesses is the easy part — a scanner hands you hundreds. The
profession is deciding which of them actually matter, fixing those first, and
then, from a flood of alerts, recognising the moment one is being exploited. This
module covers both halves: vulnerability management and the SOC.

By the end you will be able to:
- scan a web server with Nikto and prioritise findings with CVSS + KEV + EPSS +
  context;
- explain why weak passwords fall to Hydra and John, and why MFA is the fix;
- triage SIEM alerts, separate signal from noise, and correlate them into one
  attack story.

---

## 1. The big picture: vulnerability management is a loop

It is a cycle, not a one-off scan: **discover → prioritise → remediate → verify →
repeat.** Scanning is trivial; the hard, valuable work is **prioritisation**,
because you can never fix everything at once.

Four inputs make a defensible priority score:

- **CVSS** — a 0–10 *severity* score for the vulnerability in the abstract. Useful,
  but it describes the flaw, not *your* exposure.
- **CISA KEV** — the Known Exploited Vulnerabilities catalogue: a free, daily list
  of CVEs *being actively exploited in the wild right now*. If it is in KEV, it is
  no longer theoretical.
- **EPSS** — the Exploit Prediction Scoring System: the probability a CVE will be
  exploited in the next 30 days. It helps rank the long tail that isn't yet in
  KEV.
- **Context** — is it internet-facing? on a critical asset? reachable?

The decisive insight: **a medium-CVSS vulnerability that is internet-facing, on
a critical system, and listed in KEV beats a "critical" CVSS flaw that is
internal and never exploited.** Context wins over the raw number, every time.

## 2. The SOC and alert triage

The **Security Operations Centre** is the team (or person) watching the alerts,
usually tiered: **Tier 1** triages, **Tier 2** investigates, **Tier 3** hunts and
handles the hard cases. Their core skill is **triage** — for each alert, decide
**True Positive / False Positive / Needs Investigation**, and escalate what
matters. The tooling: a **SIEM** (Security Information and Event Management, e.g.
Wazuh) aggregates logs and raises alerts; **SOAR** automates the repetitive
response. Two metrics govern the SOC's effectiveness: **MTTD** (mean time to
detect) and **MTTR** (mean time to respond) — lower is better, and both appear in
board packs.

The enemy is **alert fatigue**: thousands of low-value alerts a day, until a
tired analyst starts waving everything through — which is precisely when the real
attack slips past.

## 3. How the tools actually work

**Nikto** scans web servers specifically — dangerous files, leftover backups,
outdated software, missing security headers. Where Nmap says *port 80 is open*,
Nikto says *what is wrong with what's running on it*: an exposed `/admin/`, a
`config.php.bak` leaking database credentials, a `phpinfo.php` spilling internals.

```
nikto -h http://10.13.4.10
```

**Password attacks**, in two flavours — and the point is *why controls are
mandatory*, not "how to hack":

- **Hydra** — *online* guessing against a live service (SSH, web login). Noisy and
  rate-limited, but lethal against weak passwords. A **password spray** tries one
  common password across many accounts to dodge lockouts.
- **John the Ripper** — *offline* cracking of stolen password **hashes**, computed
  locally at enormous speed, with no lockout and no limit. This is why a stolen
  hash database is a disaster, and why hashes must be **salted** and slow
  (bcrypt/argon2), never raw MD5.

A password already in a wordlist is already broken. The control that makes a
cracked password *insufficient* is **MFA**.

```
hydra -l labuser -P wordlist.txt ssh://10.13.4.20
john --wordlist=wordlist.txt hashes.txt ; john --show hashes.txt
```

**SIEM triage** ties it together. The master skill is **correlation**: ten alerts
are rarely ten problems — they are usually one attack seen from ten angles.
Failed SSH logins (brute force) + a port scan + a *successful* login, all from the
*same source IP*, is not three events; it is one intrusion, and the attacker is
now inside. Brute force maps to ATT&CK **T1110**.

```
jq -r '.[] | "\(.rule.level)\t\(.rule.description)"' alerts.json | sort -rn
jq -r '.[].data.srcip // empty' alerts.json | sort | uniq -c | sort -rn
```

## 4. An analogy

A vulnerability scan is a home inspector's report listing *every* defect, from
"roof could collapse" to "one loose cupboard hinge". Treat them as equally urgent
and you'll fix hinges while the roof caves in — prioritisation is reading the
report like an adult. SOC triage is a hospital emergency room: patients (alerts)
arrive constantly; you triage — critical / fine / needs tests — because you can't
deep-treat everyone at once. Alert fatigue is the exhausted nurse waving everyone
through just as the real emergency arrives.

## 5. Scenarios — the unpatched flaw and the weak credential

### Local (Ghana)

- A SOC analyst at a Ghanaian bank at 2 a.m. sees dozens of low-severity "failed
  SSH login" alerts — easy to ignore when tired. But one source IP is behind all
  of them, and minutes later there is an "authentication success" from that same
  IP, then a "sudo to root". Individually: noise. **Correlated: a brute-force
  that succeeded and escalated to admin.** The breached institutions had the
  alerts; they just didn't correlate them in time.

### International (well-documented)

- **Equifax, 2017.** The breach exploited **CVE-2017-5638** in Apache Struts — a
  vulnerability with a patch available for *months*. A functioning vulnerability-
  management loop (discover → prioritise → remediate → verify) would have closed
  it. This is the cost of a broken loop.
- **Colonial Pipeline, 2021.** Ransomware that halted fuel to the US east coast
  entered through a single **reused VPN password with no MFA**. Not an exotic
  exploit — a credential-and-MFA failure, exactly what Hydra/John exist to warn
  you about.

## 6. Why it matters

- Prioritisation turns an unmanageable scan report into a short, fundable
  remediation list leadership can approve.
- Understanding password cracking is the argument that finally gets MFA deployed.
- Correlation is what converts raw alerts into an actionable incident *before* the
  damage is done.

## 7. Common mistakes

- **Chasing CVSS alone** — a 9.8 nobody can reach matters less than a 6.5 on your
  internet-facing payroll box that's in KEV.
- **Using Hydra/John outside the lab** — only authorised targets and the provided
  hashes; anywhere else is a crime.
- **Closing alerts to clear the queue** — "resolved" without investigation is how
  breaches hide.
- **Ignoring low-severity floods** — volume *is* a signal; many low alerts from one
  source can be a single high-severity attack.

## Key takeaways

- Vulnerability management is a **loop**: discover → prioritise → remediate →
  verify.
- Prioritise by **CVSS + KEV + EPSS + context** — never CVSS alone.
- **Hydra** = online guessing; **John** = offline hash cracking; **salting + MFA**
  defeat them.
- SOC triage = **TP / FP / investigate**; the real skill is **correlation**.
  Watch **MTTD/MTTR**. Brute force = **T1110**.

## Check yourself

1. **CVSS 9.1 on an internal test box (not in KEV) vs CVSS 6.8 on your public
   payment portal, listed in KEV. Which first, and why?**
   → The 6.8 — internet-facing, critical asset, and *actively exploited* (KEV).
   Context and exploitation beat the raw score.

2. **What does the CISA KEV catalogue tell you that CVSS does not?**
   → Whether the vulnerability is being *actively exploited in the wild right
   now* — turning a theoretical score into a present threat.

3. **Hydra vs John — the core difference?**
   → Hydra guesses against a live service (online, rate-limited); John cracks
   stolen hashes locally (offline, no lockout, very fast).

4. **Failed logins, a port scan and a successful login — all from 10.0.0.9. How
   many incidents, and what's the skill being tested?**
   → One incident — a successful intrusion. The skill is **correlation** by shared
   indicator (the source IP).

5. **A cracked password is bad; what single control makes it insufficient on its
   own?**
   → MFA.

## Glossary

- **CVSS / CVE** — severity score / catalogue id for a vulnerability.
- **CISA KEV** — vulnerabilities known to be actively exploited.
- **EPSS** — predicted probability a CVE will be exploited soon.
- **Nikto** — web-server vulnerability scanner.
- **Hydra / John** — online password guesser / offline hash cracker.
- **Hash / salt** — a password's fingerprint / per-password randomness that
  defeats precomputed cracking.
- **SIEM / SOAR** — alert aggregation / automated response.
- **MTTD / MTTR** — mean time to detect / respond.
- **Triage / correlation** — classifying alerts / linking them into one story.
